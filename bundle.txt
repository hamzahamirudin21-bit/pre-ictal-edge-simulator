# Design: Module 1 - Synthetic Signal Generator

> EDUCATIONAL SIMULATION ONLY. All data is synthetic. This is NOT a medical device and makes no clinical claims.

Parameter ranges and defaults are defined once, in the table in `requirements.md`. This document refers to them and does not redefine them.

## Layout
```
index.html                 Vite demo page (static disclaimer banner, plots)
package.json, vite.config.js
src/
  disclaimer.js            DISCLAIMER_TEXT constant + renderDisclaimer(el)
  main.js                  demo wiring (only impure code)
  generator/
    README.md              module docs with disclaimer and clamp documentation
    prng.js                mulberry32, gaussian (Box-Muller), deriveSeed
    params.js              DEFAULTS, validateParams -> frozen resolved params
    hrv.js                 resolveHrv (shift + clamp), generateRRSeries
    ppg.js                 renderPPG(beatTimes, n, fs, rng)
    imu.js                 generateIMU
    artifact.js            lowpassZeroPhase, computeArtifact
    spectrum.js            bandEnergy(signal, fs, lo, hi) (Goertzel/DFT), used by tests and demo
    index.js               generateSignals(params) -> output
test/
  prng.test.js, params.test.js, hrv.test.js, ppg.test.js,
  imu.test.js, artifact.test.js, generator.test.js,
  generator.property.test.js
```

## Determinism
`createRng(seed)` returns `{next(), gaussian()}` with state local to the call (mulberry32). `deriveSeed(seed, label)` is the **only** way sub-stream seeds are produced: it hashes the seed and a string label (e.g. `"rr"`, `"ppg"`, `"motion"`, `"tremor"`, `"noise"`) to a 32-bit integer. No XOR shortcuts. Each component owns its stream, so changing `tremorIntensity` cannot shift draws used by motion, noise, or HRV. Tremor schedule and phases depend only on the seed and duration, never on the intensity.

Seed validation lives in `params.js`: `TypeError` if not a number, `RangeError` if non-integer or outside 0..4294967295.

## API
```js
generateSignals(params?) => {
  synthetic: true, seed, fs, durationSec, n,
  ppg, ppgClean, artifact,          // Float64Array(n)
  accel: { x, y, z },               // Float64Array(n), in g
  beatTimes,                        // Float64Array, seconds, strictly increasing
  meta: {
    effectiveHrBpm, effectiveSdnnMs, lfhf,
    clamped: { hr, sdnn },
    tremorBursts: [{ onsetSec, durationSec, freqHz }]
  }
}
```
Pure: returns new arrays, never mutates inputs; `params.js` freezes resolved params. All arrays are `Float64Array`, including `beatTimes`.

## Components

### HRV (`hrv.js`)
`resolveHrv(hr, sdnn, k)` implements requirements R3.4 and R4.1 exactly:
```
effHr     = min(hr * (1 + 0.1k), 180)          clamped.hr   = (unclamped > 180)
meanRr    = 60000 / effHr
sdnnCap   = min(150, (meanRr - 300)/2.5, (2000 - meanRr)/2.5)
shiftedSd = sdnn * (1 - 0.5k)
effSdnn   = min(shiftedSd, sdnnCap)            clamped.sdnn = (shiftedSd > sdnnCap)
lfhf      = 1 + 3k
```
Rationale for the cap: LF and HF sinusoids with total SD `s` have a peak of at most `2s`; factor 2.5 leaves margin for beat-to-beat jitter, so RR stays within [300, 2000] ms and the final RR clamp never alters valid series. The constants (0.1, 0.5, 3) are named, illustrative simulation values.

`generateRRSeries`: mean RR `meanRr` ms; variability is an LF sinusoid (~0.1 Hz) plus an HF sinusoid (~0.25 Hz) with random phases, power split per `lfhf`, plus small jitter, scaled so total SD equals `effSdnn`. The RR clamp [300, 2000] is a safety net. Cumulative sum gives beat times until `durationSec` plus one beat. For SDNN accuracy (R3.7) the sinusoid amplitudes are fixed from `effSdnn` and the sample SD is measured over whole beats.

### PPG (`ppg.js`)
Per beat, a pulse = systolic Gaussian + smaller diastolic Gaussian (dicrotic notch), with small beat-to-beat width variation. Sum over beats, normalize so peak is about 1, add respiratory baseline wander (~0.25 Hz, amplitude 0.05), then clip to [-1.5, 1.5].

### IMU (`imu.js`)
- Gravity: `[0,0,1]` rotated by pitch then roll (degrees); magnitude stays 1 g.
- Motion: sum of sinusoids in 0.3-2 Hz with random phases per axis, normalized so peak is at most 1, scaled by `0.5 * motionIntensity` g.
- Noise: Gaussian clipped at 4 sigma, sigma `0.005 + 0.01 * motionIntensity` g (at most 0.06 g).
- Tremor: a **sequential, non-overlapping** burst schedule from the tremor stream: at least one burst fully inside the recording (guaranteed by min duration 5 s), burst length in [1.5, min(5, 0.8 * duration)] s, gaps from the RNG, each burst with its own frequency in [3, 6] Hz, Hann envelope, and per-axis phase and gain in [0.5, 1]. Amplitude is `0.15 * tremorIntensity` g. Schedule and phases ignore the intensity, so the tremor contribution is exactly linear in `tremorIntensity`.
- Dynamic bound: motion (at most 0.5) + tremor (at most 0.15, non-overlapping) + noise (at most 0.06) is below 0.71, under the 0.75 g bound. The clamp to 0.75 g (and the final +-4 g) is a safety net that is never active for valid inputs, which keeps the linearity in the tremor test exact.

### Artifact (`artifact.js`)
```
dynZ     = z - mean(z)                         (fixed axis: device z)
smooth   = lowpassZeroPhase(dynZ, fc = 8 Hz)   (single-pole forward then backward;
                                                non-negative kernel, unit DC gain)
artifact = artifactGain * 2.0 * smooth
ppg      = clamp(ppgClean + artifact, -3, 3)
```
Because the kernel is non-negative and sums to 1, `|smooth| <= max|dynZ| <= 0.75`, so `|artifact| <= 1.5` and `|ppgClean + artifact| <= 3`. The clamp never changes valid output. With gain 0, `artifact` is all zeros (no floating-point residue) and `ppg` equals `ppgClean`. Using a fixed axis removes the sign ambiguity of a "dominant direction" and makes the correlation thresholds testable.

### Spectrum helper (`spectrum.js`)
`bandEnergy(signal, fs, loHz, hiHz)`: remove the mean, apply a DFT or Goertzel sum over bins in [lo, hi], return total energy. `tremorBandEnergy(accel, fs)` sums it over x, y, z for 3-6 Hz.

## Correctness properties (fast-check)
Parameter arbitraries draw from the table in `requirements.md`.

1. **P1 Determinism:** equal params and seed give deeply equal output (`Float64Array` equality).
2. **P2 Length:** `ppg`, `ppgClean`, `artifact`, `accel.x/y/z` all have length `round(duration * fs)`.
3. **P3 Bounds:** `ppgClean` in [-1.5, 1.5], `ppg` in [-3, 3], `artifact` in [-1.5, 1.5], accel in [-4, 4], all finite, all arrays are `Float64Array`.
4. **P4 Tremor energy:** for fixed seed and other params, take `t1 < t2` with `t2 - t1 >= 0.1`, and let `D(t) = accel(t) - accel(0)`. Then `tremorBandEnergy(D(t2)) > tremorBandEnergy(D(t1))`, and `energy(D(t)) ~ t^2 * energy(D(1))` within 1e-6 relative error. Also `tremorBandEnergy(accel(1)) > tremorBandEnergy(accel(0))`.
5. **P5 Artifact at gain 0:** `artifact` all zeros and `ppg` equals `ppgClean`.
6. **P6 Beat times:** strictly increasing.
7. **P7 Pre-ictal monotonic:** for `k1 <= k2`, `effectiveSdnnMs` (pre-cap shifted value) non-increasing, `effectiveHrBpm` non-decreasing, `lfhf` non-decreasing; clamp flags are consistent with R3.4.
8. **P8 Artifact correlation:** when gain > 0 and RMS(dynZ) >= 0.01 g, Pearson(`artifact`, `lowpass(dynZ)`) >= 0.999; with `motionIntensity >= 0.3`, Pearson(`artifact`, `accel.z`) >= 0.9.
9. **P9 Feasibility:** RR intervals (differences of `beatTimes`) lie in [0.3, 2.0] s for all valid inputs, and `effectiveHrBpm <= 180`.
10. **P10 Input immutability:** the params object is not mutated.

Unit tests also check sample SDNN against `effectiveSdnnMs` (R3.7) for durations of at least 30 s.

## Error handling
`validateParams` throws `TypeError` for non-numeric and `RangeError` for out-of-range or non-finite inputs (including non-integer `seed` and `fs`), with messages naming the field and valid range.

## Disclaimer
`src/disclaimer.js` exports `DISCLAIMER_TEXT` and `renderDisclaimer(el)`. `index.html` includes a static banner (visible without JS) and `main.js` also renders it. Plots are captioned "Synthetic data". The pre-ictal-like control is labeled "Pre-ictal-like (simulation knob, not clinical)". `src/generator/README.md` and the JSDoc open with the disclaimer and document the feasibility clamp.

# Requirements: Module 1 - Synthetic Signal Generator

> EDUCATIONAL SIMULATION ONLY. All data is synthetic. This is NOT a medical device and makes no clinical claims. See `.kiro/steering/disclaimer-and-safety.md`.

## Introduction
Module 1 of a browser-based educational simulator of an edge-ML wearable pipeline (PPG + IMU sensor fusion). It produces synthetic PPG and 3-axis accelerometer signals, including a tunable "pre-ictal-like" HRV pattern (a simulation knob, not a clinical claim) and a motion artifact in the PPG correlated with acceleration. Later modules consume its output.

## Technical constraints
- Vanilla JavaScript (ES modules), no framework.
- Vite (dev/build), Vitest (tests), fast-check (property-based tests).
- All generator code is pure and deterministic given a seed. No `Math.random`, `Date.now`, or global state inside generator functions.
- All signal arrays are `Float64Array`.

## Parameter table (single source of truth)

| Parameter | Type / unit | Range | Default |
|---|---|---|---|
| `seed` | integer | 0 to 4294967295 | 1 |
| `durationSec` | number, s | 5 to 600 | 30 |
| `fs` | integer, Hz | 25 to 256 | 64 |
| `heartRateBpm` | number | 40 to 180 | 70 |
| `hrvSdnnMs` | number, ms | 0 to 150 | 50 |
| `preIctalLikeness` | number | 0 to 1 | 0 |
| `motionIntensity` | number | 0 to 1 | 0.2 |
| `tremorIntensity` | number | 0 to 1 | 0 |
| `orientation.pitchDeg`, `orientation.rollDeg` | number, degrees | -180 to 180 | 0, 0 |
| `artifactGain` | number | 0 to 1 | 0.5 |

The minimum `fs` of 25 Hz keeps the 3-6 Hz tremor band safely below Nyquist. The minimum duration of 5 s guarantees at least one full tremor burst and a non-empty output.

## Requirements

### R1: Seeded deterministic randomness
**User story:** As a learner, I want reproducible signals so that I can compare runs.
1. WHEN a seed is given THEN the PRNG SHALL produce a repeatable sequence in [0, 1).
2. WHEN the same seed and parameters are given THEN the generator SHALL return deeply equal output.
3. WHEN different seeds are given THEN outputs SHALL differ.
4. The generator SHALL NOT mutate its inputs or use shared mutable state; PRNG state SHALL be local to each call.
5. Independent random sub-streams for each component (RR/HRV, PPG details, IMU motion, tremor, noise) SHALL be derived from the seed through a single `deriveSeed(seed, label)` function, so changing one parameter does not change the random draws of another component.
6. `seed` SHALL be validated: a non-number SHALL throw `TypeError`; a non-integer or a value outside the table range SHALL throw `RangeError`.

### R2: Output format
1. Every signal array (`ppg`, `ppgClean`, `artifact`, `accel.x`, `accel.y`, `accel.z`, and `beatTimes`) SHALL be a `Float64Array`. Sampling rate `fs` is fixed per output and defaults to 64 Hz.
2. Sample count of `ppg`, `ppgClean`, `artifact`, and each accel axis SHALL equal `n = round(durationSec * fs)`. `beatTimes` has a variable length.
3. The output object SHALL contain: `synthetic: true`, `seed`, `fs`, `durationSec`, `n`, `ppg` (with artifact), `ppgClean` (before artifact), `artifact`, `accel: {x, y, z}`, `beatTimes` (seconds), and `meta` (see R3.5, R4.4, R5.5).
4. All samples SHALL be finite numbers (no NaN/Infinity).
5. Parameters outside the table ranges SHALL throw `RangeError`; wrong types SHALL throw `TypeError`; messages SHALL name the field and its valid range. Omitted parameters SHALL take the table defaults.

### R3: PPG with configurable HR and HRV
1. The user SHALL configure mean heart rate (`heartRateBpm`) and HRV amount (`hrvSdnnMs`) within the table ranges.
2. The generator SHALL build an RR-interval series with the effective mean and approximately the effective SDNN (R3.4), having low-frequency and high-frequency components, then render a pulse waveform per beat.
3. `beatTimes` SHALL be strictly increasing.
4. **Feasibility clamp.** Effective values SHALL be computed as:
   - `effHr = min(hr * (1 + 0.1 * preIctalLikeness), 180)`.
   - `meanRrMs = 60000 / effHr`.
   - `sdnnCap = min(150, (meanRrMs - 300) / 2.5, (2000 - meanRrMs) / 2.5)`.
   - `effSdnn = min(hrvSdnnMs * (1 - 0.5 * preIctalLikeness), sdnnCap)`.
   The cap guarantees that RR intervals stay within [300, 2000] ms, so the RR clamp is only a safety net that SHALL NOT alter the series for valid inputs.
5. `meta` SHALL report `effectiveHrBpm`, `effectiveSdnnMs`, `lfhf`, and `clamped: {hr: boolean, sdnn: boolean}`. WHEN a clamp applies THEN the corresponding flag SHALL be true.
6. The clamp rule SHALL be documented in the module docs and the parameter descriptions.
7. Measured SDNN of the generated RR series SHALL be within 15% of `effectiveSdnnMs` (or within 3 ms when it is below 20 ms) for durations of at least 30 s.

### R4: Pre-ictal-like HRV knob
1. `preIctalLikeness` in [0, 1] SHALL shift the HRV profile toward a pre-ictal-like pattern: reduced overall HRV (`x(1 - 0.5k)`), a higher LF/HF ratio (`1 + 3k`), and a small increase in mean heart rate (`x(1 + 0.1k)`, before the R3.4 clamp).
2. At 0 the output SHALL equal that of the unshifted configuration. `effectiveSdnnMs` (before the cap) SHALL be non-increasing, `effectiveHrBpm` non-decreasing, and `lfhf` non-decreasing in the knob.
3. Docs, parameter descriptions, and UI labels SHALL state that this is a simulation knob and not a clinical claim.
4. Constants SHALL be named and documented as illustrative simulation values.

### R5: IMU (3-axis accelerometer)
1. Output SHALL be in units of g with a static gravity component of magnitude 1 g, default on the z axis, rotated by `orientation` (pitch, roll in degrees).
2. `motionIntensity` scales low-frequency voluntary-motion-like movement (0.3-2 Hz) with peak amplitude `0.5 * motionIntensity` g per axis, plus sensor noise.
3. `tremorIntensity` adds tremor bursts with per-burst frequency in [3, 6] Hz and randomized onset and duration. At 0 no tremor is added. Bursts SHALL NOT overlap, and at least one full burst SHALL lie inside the recording.
4. **Tremor energy.** Define tremor band energy as the summed spectral energy over 3-6 Hz of the detrended signal across the three axes. For a fixed seed and other parameters:
   - the tremor-attributable energy, measured on `accel(t) - accel(0)` (the same output with `tremorIntensity` set to 0 subtracted), SHALL be strictly increasing in `tremorIntensity` and scale as its square (within 1e-6 relative error);
   - the full-signal band energy with tremor at 1 SHALL exceed the band energy with tremor at 0.
5. `meta` SHALL report `tremorBursts` (list of onset, duration, frequency).
6. The dynamic (non-gravity) part of each axis SHALL be bounded by 0.75 g by construction; clamping is a safety net only.

### R6: Motion artifact in PPG
1. The artifact SHALL be defined as `artifact = artifactGain * 2.0 * lowpass(dynZ)`, where `dynZ` is the mean-removed accel z-axis (a **fixed axis**, device z), and `lowpass` is a zero-phase single-pole low-pass at 8 Hz with non-negative kernel and unit DC gain. The artifact is a signed projection, not a magnitude.
2. `ppg = clamp(ppgClean + artifact, -3, 3)`. With `artifactGain = 0`, `artifact` SHALL be all zeros and `ppg` SHALL equal `ppgClean` exactly.
3. **Correlation thresholds.** When `artifactGain > 0` and the RMS of `dynZ` is at least 0.01 g:
   - Pearson correlation between `artifact` and `lowpass(dynZ)` SHALL be at least 0.999;
   - Pearson correlation between `artifact` and raw `accel.z` SHALL be at least 0.9 when `motionIntensity >= 0.3`.
4. `ppgClean`, `artifact`, and `ppg` SHALL all be exposed.

### R7: Bounded amplitudes
1. `ppgClean` SHALL lie in [-1.5, 1.5] (normalized units); `ppg` within [-3, 3]; `artifact` within [-1.5, 1.5].
2. Accelerometer axes SHALL lie within [-4, 4] g for all valid parameters (gravity at most 1 g plus a dynamic part of at most 0.75 g).

### R8: Disclaimer
1. The module docs (`src/generator/README.md` and JSDoc on the public API) and the demo page SHALL show the standard disclaimer from the steering doc.
2. A shared exported disclaimer constant SHALL exist and be rendered on the Vite demo page visibly without interaction; the static HTML SHALL also contain it.
3. Output SHALL include `synthetic: true`.
4. The demo page SHALL label the pre-ictal-like control as a simulation knob and plots as "Synthetic data".

### R9: Testing
1. Unit tests SHALL cover the PRNG, `deriveSeed`, parameter validation (including seed), each signal component, the feasibility clamp, and defaults.
2. Property-based tests (fast-check) SHALL cover: same seed gives same output; sample count equals duration x rate; amplitudes bounded; tremor energy rises with the tremor parameter (R5.4).
3. Additional properties: finite samples; artifact zero when gain is 0; strictly increasing beat times; pre-ictal knob monotonicity (SDNN, HR, LF/HF); artifact correlation thresholds (R6.3); arrays are `Float64Array`.
4. Generators for property tests SHALL draw parameters from the table ranges in this document.

# Disclaimer and Safety Policy

## Core statements (non-negotiable)
- All data in this project is **synthetic**. No real patient or sensor data is used or collected.
- This project is **NOT a medical device**.
- It makes **no clinical claims**. It does not detect, predict, diagnose, monitor, or prevent seizures or any condition.
- "Pre-ictal-like" refers to a tunable simulation parameter for teaching, never a clinical finding.

## Required disclaimer text
Use this wording (or a stricter variant) everywhere:

> EDUCATIONAL SIMULATION ONLY. All data is synthetic. This is NOT a medical device and makes no clinical claims. Do not use it for any medical decision.

## Rules
1. `README.md` must show the disclaimer prominently at the top.
2. Every user-facing screen/page/view must display a clear, visible disclaimer (not hidden in a tooltip or collapsed by default). Provide one shared disclaimer component/constant and reuse it.
3. Never use language implying clinical validity: avoid "detects seizures", "predicts", "diagnosis", "accuracy for patients", "clinically validated". Use "simulated", "synthetic", "illustrative".
4. Label generated signals and charts as synthetic.
5. Spec requirements, tasks, and UI copy for new modules must include a disclaimer-visibility check.
6. Parameter names and docs describing the pre-ictal-like knob must state it is a simulation knob.

 *

export const DEFAULTS = Object.freeze({
  seed: 1,
  durationSec: 30,

function isPlainObject(value) {
  return typeof value === 'object' && value !== null && !Array.isArray(value);
}

/**
 * Validate one numeric field and return its value (or the default if omitted).
 * @param {string} name field name used in error messages
 * @param {unknown} value
 * @param {number} fallback default used when value is undefined
 */
function checkNumber(name, value, fallback) {
  if (value === undefined) return fallback;
  if (typeof value !== 'number') {
    throw new TypeError(`${name} must be a number, got ${value === null ? 'null' : typeof value}`);
  }
  const [min, max] = RANGES[name];
  if (!Number.isFinite(value) || value < min || value > max) {
    throw new RangeError(`${name} must be a finite number in [${min}, ${max}], got ${value}`);
  }
  if (INTEGER_FIELDS.has(name) && !Number.isInteger(value)) {
    throw new RangeError(`${name} must be an integer in [${min}, ${max}], got ${value}`);
  }
  return value;
}

    throw new TypeError('params must be an object');

    pitchDeg: checkNumber('pitchDeg', orientationIn.pitchDeg, DEFAULTS.orientation.pitchDeg),
    rollDeg: checkNumber('rollDeg', orientationIn.rollDeg, DEFAULTS.orientation.rollDeg),
  });

  return Object.freeze({
    seed,
    durationSec: checkNumber('durationSec', input.durationSec, DEFAULTS.durationSec),
    fs: checkNumber('fs', input.fs, DEFAULTS.fs),
    heartRateBpm: checkNumber('heartRateBpm', input.heartRateBpm, DEFAULTS.heartRateBpm),
    hrvSdnnMs: checkNumber('hrvSdnnMs', input.hrvSdnnMs, DEFAULTS.hrvSdnnMs),

    motionIntensity: checkNumber('motionIntensity', input.motionIntensity, DEFAULTS.motionIntensity),
    tremorIntensity: checkNumber('tremorIntensity', input.tremorIntensity, DEFAULTS.tremorIntensity),

    artifactGain: checkNumber('artifactGain', input.artifactGain, DEFAULTS.artifactGain),

export const SEED_MIN = 0;
export const SEED_MAX = 4294967295;

/**
 * Check that a seed is an integer in [0, 4294967295].
 * @param {unknown} seed
 * @returns {number} the same seed
 * @throws {TypeError} if seed is not a number
 * @throws {RangeError} if seed is not an integer or is out of range
 */
export function validateSeed(seed) {
  if (typeof seed !== 'number') {
    throw new TypeError(`seed must be a number, got ${seed === null ? 'null' : typeof seed}`);
  }
  if (!Number.isInteger(seed) || seed < SEED_MIN || seed > SEED_MAX) {
    throw new RangeError(`seed must be an integer in [${SEED_MIN}, ${SEED_MAX}], got ${seed}`);
  }
  return seed;
}

/**
 * Create a mulberry32 random generator. State is local to the returned object.
 * @param {number} seed integer in [0, 4294967295]
 * @returns {{ next: () => number, gaussian: () => number }}
 */
export function createRng(seed) {
  validateSeed(seed);
  let state = seed >>> 0;

  /** Uniform number in [0, 1). */
  function next() {
    state = (state + 0x6d2b79f5) >>> 0;
    let t = state;
    t = Math.imul(t ^ (t >>> 15), t | 1);
    t ^= t + Math.imul(t ^ (t >>> 7), t | 61);
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
  }

  /** Standard normal number (mean 0, sd 1) using the Box-Muller transform. */
  function gaussian() {
    const u1 = 1 - next(); // in (0, 1], so log(u1) is finite
    const u2 = next();
    return Math.sqrt(-2 * Math.log(u1)) * Math.cos(2 * Math.PI * u2);
  }

  return { next, gaussian };
}
/**
 * Derive an independent 32-bit seed for a named component from a base seed.
 * The same (seed, label) always gives the same result; different labels give
 * different, unrelated streams.
 * @param {number} seed base seed, integer in [0, 4294967295]
 * @param {string} label component name, for example "rr" or "tremor"
 * @returns {number} integer in [0, 4294967295]
 */
export function deriveSeed(seed, label) {
  validateSeed(seed);
  if (typeof label !== 'string' || label.length === 0) {
    throw new TypeError('label must be a non-empty string');
  }
  // FNV-1a over the label, mixed with the seed, then a murmur3-style finalizer.
  let h = (0x811c9dc5 ^ seed) >>> 0;
  for (let i = 0; i < label.length; i++) {
    h ^= label.charCodeAt(i);
    h = Math.imul(h, 0x01000193) >>> 0;
  }
  h ^= h >>> 16;
  h = Math.imul(h, 0x85ebca6b) >>> 0;
  h ^= h >>> 13;
  h = Math.imul(h, 0xc2b2ae35) >>> 0;
  h ^= h >>> 16;
  return h >>> 0;
}

function take(rng, n, fn = 'next') {
  const out = [];
  for (let i = 0; i < n; i++) out.push(rng[fn]());
  return out;
}

const mean = (xs) => xs.reduce((a, b) => a + b, 0) / xs.length;

describe('createRng', () => {

  });

  });
